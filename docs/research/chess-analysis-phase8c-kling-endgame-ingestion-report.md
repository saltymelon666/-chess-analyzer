# Chess Analysis Phase 8C Kling/Horwitz Endgame Ingestion Report

## 结果

第二批12个图盘全部通过人工审核。两轮合计28个棋盘均已有明确裁决；本轮没有把棋盘识别置信度当成最终正确性证明。

恢复原书图注、行棋方和目标后，按证据强度分为：

- 20题：棋子摆放与行棋方完整，原书胜和结论与七子表完全一致；已保留Syzygy审计结果和经过`python-chess`合法性验证的关键首着。
- 3题：棋子超过七个，Stockfish Depth 20、MultiPV 3支持原书结论；因为不属于七子表精确证明，只保留为研究证据，未进入运行时残局库。
- 1题：KH-007原书写“白先胜”，七子表精确判定为和棋；作为历史结论冲突隔离。
- 2题：原书图注没有保留完整目标。
- 2题：原书只写某方胜，但没有明确行棋方。

## 只读残局查询层

新增`EndgameKnowledgeRepository`和`POST /api/endgame-lookup`。运行时数据只包含20个`exact_verified`条目，并同时要求棋子摆放与行棋方完全一致。

接口返回：

- 原书及页码；
- 原书简短结果图注；
- Syzygy胜和类别、DTZ/DTM；
- 经合法性校验的关键首着；
- 明确的权威边界。

接口不调用Stockfish或DeepSeek，不进行相似局面迁移，不返回冲突、缺失或仅有普通引擎支持的条目。当前也没有把残局条目文本注入DeepSeek Prompt。

## 数据边界

`phase8c-kling-endgame-dataset.json`保留全部28题及其不同证据状态。`app/data/endgame-knowledge.json`是运行时压缩副本，只导出20题七子表精确验证条目。

七子表批量展开多步路线时外部接口出现429限流，因此正式运行时只固化已经审计的根局面结果与关键首着；没有把失败请求伪装为完整路线。多步原书旧式记谱转换仍是后续研究任务。
